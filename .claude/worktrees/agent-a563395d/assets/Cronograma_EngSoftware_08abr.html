⚡ Resumo Rápido — o que mais caiu
▼
★ Manifesto Ágil — 3/3 provas
EntregasSoftware funcional em ciclos curtos e frequentes > documentação extensa
MudançasÁgil abraza mudanças de requisitos; tradicional resiste e congela o escopo
EquipeÁgil: equipe autogerenciáda, papéis flexíveis; tradicional: hierárquica, papéis rígidos
ClienteColaboração contínua com o cliente durante todo o projeto
★ Modelos de Processo — 3/3 provas
CascataFases sequenciais e rígidas. Só funciona se os requisitos já são bem conhecidos
IncrementalEntrega em partes. Ideal quando os requisitos não são totalmente conhecidos
EspiralCiclos iterativos com análise de riscos. Incompatível com cronograma fechado no início
PrototipagemGera versões rápidas para validação. Útil quando o cliente não sabe o que quer
4ª GeraçãoFerramentas automatizadas. Vantagem: rapidez. Desvantagem: dependência e limitações
Codifica-RemendaAnti-modelo: codifica sem planejamento e "remenda" erros. Gera caos e dívida técnica
★ Requisitos de Software — 3/3 provas
FuncionaisO que o sistema faz. Ex: "o sistema deve permitir login com e-mail"
Não-FuncionaisComo o sistema se comporta. Ex: desempenho, segurança, disponibilidade
ImplícitosNão documentados, causam retrabalho e conflito. Solução: elicitação detalhada
LegaisNão podem ser ignorados mesmo que o cliente peça. A responsabilidade é da equipe
ObservacionaisTécnicas mais realistas. Prós: captura o real. Contras: demorado, pode constranger
▲ Natureza do Software — 2/3 provas
Não desgastaSoftware não se deteriora pelo uso, mas torna-se obsoleto por evolução do ambiente
ManutençãoO trabalho do engenheiro não termina com a entrega: manutenção, evolução e suporte continuam
Sob encomendaA maior parte do software é desenvolvida sob demanda, não como produto de prateleira
● Gerenciamento — 1/3 provas
Lei de BrooksAdicionar pessoas a um projeto atrasado o atrasa ainda mais — curva de aprendizado + sobrecarga de comunicação
MitosGerente: "mais gente = mais rápido". Engenheiro: "entreguei, acabei". Cliente: "requisito geral basta"
01/04 Qua
Introdução — Software, Tipos e Características
HOJE
▼
IntroduçãoEstudar o que é Engenharia de Software e por que ela existe — diferenciar de simples programação
TiposMemorizar os 5 tipos de software: Uso pessoal, Comercial/Negócios, Engenharia/Científico, De sistema, Embarcado — com um exemplo de cada
CaracterísticasEntender as 3 características: não desgasta, não é fabricado, maior parte é feito sob encomenda — saber explicar cada uma com argumentação
PráticaEscrever à mão um parágrafo dissertativo: definição de software + por que ele se torna obsoleto mesmo sem desgastar
Atenção: Obsolescência de software caiu na prova de 2023 citando Pressman. Saiba explicar por que o software não desgasta, mas se torna obsoleto, e quais as consequências disso para o engenheiro.
02/04 Qui
Mitos da Engenharia de Software
MITOS
▼
GerenteEstudar os mitos do gerente: ex. "adicionar mais programadores a qualquer momento acelera o projeto" — conectar com a Lei de Brooks (caiu em 2024!)
EngenheiroEstudar os mitos do engenheiro: ex. "ao terminar o código, o trabalho do engenheiro acabou" — saber rebater com manutenção e evolução (caiu em 2024!)
ClienteEstudar os mitos do cliente: ex. "um enunciado geral é suficiente para começar" e "o que importa é entender o que se vai codificar"
PráticaTreinar: escrever a refutação de cada mito em 2–3 frases como se fosse uma questão dissertativa da prova
Dica da prova: A questão da 2024 perguntou se adicionar desenvolvedores "a qualquer momento" acelera o projeto — a resposta é não, e você precisa explicar por quê (curva de aprendizado, comunicação, Lei de Brooks). Treine essa argumentação.

04/04 Sáb
Modelos Tradicionais — Cascata, Prototipagem e Incremental
MODELOS
▼
CascataEstudar o Modelo Cascata: fases sequenciais rígidas, quando é indicado (requisitos bem definidos), e por que falha quando os requisitos não são conhecidos — caiu em 2024!
PrototipagemEstudar Prototipagem: quando o cliente não sabe bem o que quer, geração rápida de versões para validação antes do desenvolvimento final
IncrementalEstudar Modelo Incremental: entrega em partes (incrementos), adequado quando os requisitos não são totalmente conhecidos desde o início — caiu em 2023!
Codifica-RemendaEntender o modelo Codifica-Remenda: o "anti-modelo", sem planejamento, por que ele é problemático e gera dívida técnica
PráticaTreinar a resposta dissertativa: "Elisa usa Cascata. Os requisitos não são bem conhecidos. O processo é adequado? Qual deveria usar?" — responder em parágrafo
Questão-padrão do professor: Nas 3 provas analisadas, apareceu a situação "Elisa usa modelo X, mas os requisitos não são bem conhecidos." Treine a resposta para Cascata, Incremental e Espiral separadamente.
05/04 Dom
Modelos Espiral, 4ª Geração/RAD e revisão geral dos modelos
MODELOS
▼
EspiralEstudar o Modelo Espiral: ciclos iterativos com análise de riscos em cada volta. Por que um cronograma fechado no início é incompatível com ele? — caiu em 2024!
4ª GeraçãoEstudar modelos de 4ª geração/RAD: uso de ferramentas automatizadas de desenvolvimento, quais as vantagens (rapidez, menos código manual) e desvantagens (dependência, limitações) — caiu em 2024!
RevisãoRevisar todos os 6 modelos juntos: Cascata, Prototipagem, Incremental, Espiral, 4ª Geração/RAD, Codifica-Remenda — e saber indicar o mais adequado para cada cenário
PráticaSimular: "Elisa usa Espiral. O cliente pede cronograma fechado no início. É compatível? Para qual outro modelo ela deveria mudar?" — escrever em parágrafo completo
Todos os modelos caem: Modelos de processo apareceram nas 3 provas analisadas, sempre com cenários práticos. Conhecer as vantagens, limitações e cenários de uso de cada um é fundamental.
