# Mission Discipline Bubbles

## Mission
Turn dense “daily mission” pages into **simple discipline-centered study hubs**.

The page should stop trying to explain everything at once.
Instead, it should help the user answer only this:

- What subjects matter today?
- Which one should I open first?
- What is inside each one?
- What can I do right now?

The unit of navigation should be the **discipline**, not the graph, not the metric, not the system explanation.

---

## Use this skill when
Use this skill when:
- the daily mission page is too dense
- there are too many metrics, graphs, and explanatory blocks
- the user cannot quickly understand what to open first
- the page should behave more like a smart launcher than a full dashboard
- the product needs progressive disclosure
- the user explicitly asks for discipline “bubbles”, expandable subject cards, or simpler mission logic

---

## Do not use this skill when
Do not use this skill when:
- the page truly needs heavy analytics as the main purpose
- the task is a pure dashboard KPI page
- the product unit is not the discipline/content area
- the user needs a reporting tool instead of an action-oriented hub

---

## Core philosophy
The daily mission should organize the day, not narrate the system.

The landing state must be light.
Details appear only when the user chooses to expand.

This skill should always prioritize:
- clarity over completeness
- expansion over overload
- subject-first navigation
- short signals over explanation
- action readiness over system storytelling

---

## Primary UI model
The default page should show a list or grid of **discipline bubbles/cards**.

Each discipline card should show only:
- discipline name
- priority state
- short progress/state cue
- item count or compact summary
- expand affordance

When expanded, the card may reveal:
- 3 to 5 suggested questions
- 1 to 2 relevant content items
- optional review cue
- one primary CTA

---

## Non-negotiable principles

### 1. Discipline is the main unit
The user must first see disciplines, not supporting metrics.

### 2. Progressive disclosure
Never dump everything open at once.
Details must be hidden by default.

### 3. Small entry, meaningful expansion
The collapsed state should be extremely light.
The expanded state should still remain clean and focused.

### 4. One next move per discipline
Every expanded discipline should make the next action obvious.

### 5. Quiet visual hierarchy
This should feel elegant and calm, not like a cluttered academic portal.

---

## Recommended structure
A strong version of this pattern usually has:

### Top layer
- “Daily Mission” title
- very short daily status
- maybe one minimal summary line

### Main layer
- priority-sorted discipline cards/bubbles

### Expanded layer
Inside each card:
- question preview list
- content preview list
- review or recovery cue if needed
- single CTA

### Secondary layer
System details, XP, explanatory material, long summaries, or secondary analytics should be:
- removed
- re-ranked
- or moved down the page

---

## Visual language
Aim for:
- soft premium cards
- obvious active/expanded state
- strong card titles
- low-text preview items
- clear expansion rhythm
- calm dark UI
- enough spacing to avoid cognitive overload

Avoid:
- giant dashboards on the mission page
- many chart types competing
- paragraph-heavy cards
- dense multi-column clutter
- overcomplicated learning widgets

---

## Workflow

### Step 1 — Identify overload
Find:
- which blocks are not helping the user start
- which metrics belong elsewhere
- where the page becomes confusing
- what is distracting from discipline selection

### Step 2 — Reduce the top layer
Keep only what helps the user orient quickly.

### Step 3 — Promote disciplines
Make disciplines the visual and logical center of the page.

### Step 4 — Design expansion
Each expanded state should reveal only the minimum viable inside layer.

### Step 5 — Make the next action obvious
A discipline should never expand into a vague information dump.

### Step 6 — Re-rank secondary content
Move non-essential material down or out.

---

## Quality bar
A successful result should make the user feel:
- “Now I understand my day”
- “I know what to open first”
- “This is much simpler”
- “The system feels helpful, not overwhelming”

---

## Anti-patterns
Do not produce:
- a daily mission page that still behaves like an analytics wall
- cards full of paragraphs
- too much preview content per discipline
- many CTAs per discipline
- expansion states that feel like mini dashboards
- visual emptiness that looks lazy instead of intentional

---

## Final validation checklist
Before finishing, verify:
- the first screen is discipline-first
- the page is much easier to scan
- each discipline has a clear expand pattern
- each expanded state reveals only useful content
- the next action is obvious
- the page feels lighter and more premium than before
