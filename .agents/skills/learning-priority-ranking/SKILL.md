# Learning Priority Ranking

## Mission
Make learning interfaces prioritize clearly.

This skill exists to answer:
- what matters first
- what matters today
- what can wait
- what is optional

Without priority, educational interfaces become confusing.
This skill turns content piles into a clear order of attack.

---

## Use this skill when
Use this skill when:
- the page shows many disciplines or study items
- the user needs a “what first?” answer
- the interface feels flat and all items look equally important
- the daily mission needs a real order
- the product should guide, not merely display

---

## Do not use this skill when
Do not use this skill when:
- all items are intentionally equal
- the page is purely archival
- the task is only visual polish with no ordering change
- ranking would be misleading or arbitrary

---

## Core philosophy
Priority is a product decision, not a decoration.

A good ranking system should make the user feel:
- guided
- focused
- less overwhelmed
- more ready to act

This skill should always favor:
- clarity
- urgency logic
- ordered action
- reduced cognitive load

---

## Recommended priority layers
Use a structure like:
- Urgent
- Today
- Review
- Optional

Or any equivalent hierarchy that clearly separates urgency from support.

---

## Non-negotiable principles

### 1. One first thing
The page should make the first action obvious.

### 2. Priority must be visible
Users should not have to interpret subtle clues to know what matters first.

### 3. Visual weight should follow priority
Urgent items should not look identical to optional items.

### 4. Keep ranking calm
Priority should guide, not scream.

### 5. Support action, not guilt
Priority design should feel useful, not punishing.

---

## Signals you may use
Good ranking signals include:
- urgency state
- item count
- blocked progress
- recovery needs
- revision timing
- discipline importance
- due-now relevance

Use them sparingly and clearly.

---

## UI patterns to prefer
Prefer:
- ordered list by importance
- visual emphasis for the first item
- short state badges
- one clear CTA per ranked item
- grouped sections by priority layer

Avoid:
- all items styled equally
- too many priority chips
- hidden ranking logic
- loud warning-heavy UI everywhere

---

## Workflow

### Step 1 — Determine ranking logic
Understand what actually makes something more important today.

### Step 2 — Build visible priority layers
Create a readable structure for urgency tiers.

### Step 3 — Make the first item feel first
The top-ranked item should visually read as the best next move.

### Step 4 — Reduce ambiguity
The user should not wonder why something is at the top.

### Step 5 — Keep secondary items calm
Lower-priority items should still be readable, just lighter.

---

## Quality bar
A successful result should make the user feel:
- “I know what to do first”
- “This helps me focus”
- “I am not drowning in options”

---

## Anti-patterns
Do not produce:
- fake priority with no meaningful difference
- visual chaos from too many priority markers
- ranking systems that feel arbitrary
- interfaces where the urgent item is not obvious

---

## Final validation checklist
Before finishing, verify:
- there is a clear first item
- priority layers are understandable
- visual hierarchy follows ranking
- the user can act without overthinking
- the page feels more focused than before
