# Graph Lite Educational Dashboard

## Mission
Create educational dashboards where charts exist, but **do not overwhelm the mission**.

This skill is for pages that still benefit from metrics or visuals, but where the primary goal is learning flow, not analytics spectacle.

Charts should:
- support understanding
- support prioritization
- stay lightweight
- feel premium and calm
- never become noisy

---

## Use this skill when
Use this skill when:
- the page still needs graphs, but only as support
- the user needs quick visual context
- educational data should remain readable and low-noise
- the page should feel cleaner than a typical KPI dashboard
- the main product goal is study action, not reporting

---

## Do not use this skill when
Do not use this skill when:
- the chart is the entire product
- the user needs a highly analytical dashboard
- dense reporting is the main point of the page
- charts must dominate the experience

---

## Core philosophy
In education-focused interfaces, charts should clarify, not compete.

This skill must always favor:
- chart restraint
- visual calm
- readable metrics
- minimal annotation
- clear hierarchy

The chart is not the hero unless explicitly required.

---

## What this skill should achieve
The page should feel:
- visual enough
- informative enough
- never busy
- never over-analytical
- easy to scan
- aligned with the study journey

---

## Non-negotiable principles

### 1. Fewer charts
Only keep charts that help the user decide something.

### 2. Larger, calmer chart areas
If a chart exists, let it breathe.

### 3. Minimal chart annotation
Avoid too much:
- explanatory copy
- labels
- legends
- microtext
- noise

### 4. Metrics should be strong and simple
Use 2 to 3 supporting metrics max where helpful.

### 5. Educational first, analytics second
The page should still feel like a learning product.

---

## Preferred chart types
Prefer simple, readable chart patterns like:
- clean progress bars
- simple line charts
- low-noise area charts
- light donut charts
- soft grouped comparisons
- calm weekly rhythm bars

Avoid:
- dense dashboards full of chart variety
- complex multi-axis visuals
- overloaded legends
- charts that require explanation to understand

---

## Visual language
Aim for:
- dark UI with good contrast
- restrained color
- one accent per chart
- readable values
- generous whitespace
- minimal legend clutter

Avoid:
- neon overload
- busy data-heavy canvases
- tiny labels
- too many series at once

---

## Workflow

### Step 1 — Decide if the chart deserves to exist
If the user can decide just as well without it, remove or re-rank it.

### Step 2 — Simplify the data story
A chart should answer one question, not five.

### Step 3 — Reduce annotation
Cut unnecessary legend and helper copy.

### Step 4 — Strengthen the visual mass
Let the chart area breathe.

### Step 5 — Support with a tiny metrics strip if helpful
Use only a few strong metrics.

---

## Quality bar
A successful result should feel:
- calm
- useful
- readable
- premium
- light

The user should feel:
- “I get the signal”
- “The chart helps”
- “This doesn’t feel crowded”

---

## Anti-patterns
Do not produce:
- analytics theater
- explanation-heavy chart cards
- tiny hard-to-read labels
- over-decorated graphs
- 5 charts competing on one mission page

---

## Final validation checklist
Before finishing, verify:
- only useful charts remain
- charts are calmer and easier to read
- the page still feels educational first
- annotation is minimal
- the chart helps action rather than distracting from it
