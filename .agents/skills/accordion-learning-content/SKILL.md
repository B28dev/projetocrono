# Accordion Learning Content

## Mission
Create expandable learning interfaces that feel:
- light
- clear
- organized
- calm
- educational without looking bureaucratic

This skill exists to turn learning content into clean progressive layers, so users only see deeper detail when they ask for it.

---

## Use this skill when
Use this skill when:
- the page has questions, lessons, flashcards, or study items that should not all be visible at once
- the interface needs expandable learning groups
- the user needs an easy way to reveal content progressively
- a daily mission or study page needs low-noise detail layers
- content needs to be mobile-friendly and cognitively light

---

## Do not use this skill when
Do not use this skill when:
- everything must stay visible at once for a specific reason
- the structure is a table or true data grid
- the problem is shell hierarchy rather than internal expandable content

---

## Core philosophy
Educational content gets messy very quickly.

This skill should always favor:
- compact collapsed states
- informative expanded states
- one-click comprehension
- obvious grouping
- low cognitive load

The accordion should feel like:
- calm structure
- not hidden complexity
- not bureaucratic nesting
- not a giant FAQ dump

---

## Ideal use cases
This skill works especially well for:
- related questions
- lesson clusters
- content by topic
- revision sets
- flashcard groups
- daily study previews
- subject-based task previews

---

## Non-negotiable principles

### 1. Compact by default
Closed states should be small and highly scannable.

### 2. Useful when opened
Expanded states must reveal something meaningfully actionable, not filler text.

### 3. One hierarchy per block
Every accordion item needs:
- title
- compact support signal
- reveal affordance
- clean inside structure

### 4. No accordion chaos
Avoid many nested accordions unless absolutely necessary.

### 5. Mobile-first
Tap targets, spacing, open state rhythm, and text density must work on mobile.

---

## Preferred internal structure
A strong accordion item usually has:

### Collapsed state
- title
- short metadata
- count or state
- chevron / affordance

### Expanded state
- 3 to 5 related items
- optional short context label
- concise item rows
- one main CTA if needed

---

## Design rules
Prefer:
- soft dark surfaces
- subtle borders
- clean spacing
- obvious open/closed transition
- low-text metadata
- readable item stacks

Avoid:
- giant paragraphs
- overdecorated headers
- thick noisy dividers
- tiny unreadable metadata
- too many badges shouting at once

---

## Content rules
When expanded, content should still be compressed.

Good expanded content:
- short titles
- short descriptors
- state cues
- preview counts
- clear CTA

Bad expanded content:
- long explanations
- repeated metadata
- multiple redundant labels
- content that feels like an entire dashboard inside the accordion

---

## Workflow

### Step 1 — Group content properly
Cluster content by meaningful units:
- topic
- discipline
- urgency
- content type
- review state

### Step 2 — Design the collapsed state
Make sure the user can scan the list quickly.

### Step 3 — Design the expanded state
Reveal enough to be useful, but not enough to become cluttered.

### Step 4 — Refine affordance
Make expansion feel natural, visible, and calm.

### Step 5 — Validate mobile use
Check tap comfort, spacing, and readability.

---

## Motion rules
Use:
- soft expansion
- short height transitions
- subtle fade/slide
- elegant chevron motion

Do not use:
- aggressive motion
- playful bounce
- distracting delays

---

## Anti-patterns
Do not produce:
- accordions that hide important primary actions
- collapsed rows with no useful information
- expanded states with too much content
- multiple competing CTA buttons
- accordion blocks that feel like form fields

---

## Final validation checklist
Before finishing, verify:
- collapsed states are highly scannable
- expanded states are truly useful
- hierarchy is obvious
- the UI feels calm and premium
- the pattern works on mobile
- the content remains compressed even when opened
