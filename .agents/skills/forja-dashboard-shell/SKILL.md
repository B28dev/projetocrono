# Forja Dashboard Shell

## Mission
Build dashboards that feel premium, calm, intentional, and structurally confident.

This skill exists to reproduce the **reading logic** of Forja, not to imitate it literally.
The goal is:
- strong dashboard shell
- elegant dark UI
- large breathable cards
- clear navigation
- low noise
- visual focus
- premium product feeling

The result should feel:
- light, not empty
- sophisticated, not flashy
- delicate, not weak
- rich, not cluttered
- intentional, not lazy

---

## Use this skill when
Use this skill when:
- a page feels like a report instead of a product
- the shell is weak or generic
- the sidebar/header hierarchy is unclear
- too many cards compete at once
- the user wants something "like Forja"
- the interface needs to feel more premium, calm, and productized
- a dashboard needs stronger visual structure before local refinement

---

## Do not use this skill when
Do not use this skill when:
- the task is backend-only
- the task is a single isolated component without shell impact
- the main issue is data logic, not product hierarchy
- the page already has a strong shell and only needs micro polish

---

## Core design philosophy
The shell must do most of the work.

A good dashboard shell should:
- orient the user before explaining anything
- make the primary action obvious
- create visual silence around important content
- reduce friction through spacing and order
- make the product feel mature immediately

This skill should always favor:
- hierarchy over decoration
- spacing over borders
- structure over noise
- product clarity over visual tricks

---

## Non-negotiable principles

### 1. One strong shell
The page should have:
- a strong sidebar or clear navigation system
- a clean top context layer
- a readable main content zone
- clear section rhythm

### 2. Large blocks, not fragmented clutter
Prefer:
- fewer, larger blocks
- strong section grouping
- consistent card rhythm
- breathable composition

Avoid:
- many tiny panels
- too many nested containers
- busy layouts
- dashboard mosaics without hierarchy

### 3. Quiet premium dark UI
Dark UI should feel expensive and calm.
Avoid muddy contrast, noisy gradients, or too many competing accents.

### 4. Strong navigation confidence
The user should understand immediately:
- where they are
- what this area is about
- what deserves attention first

### 5. Each section must have one visual leader
A section should not contain 3 equal heroes.
One thing leads. The rest supports.

---

## Structural patterns to prefer
Prefer patterns like:
- strong left sidebar with active state
- compact top context bar
- large hero card or large primary insight block
- secondary cards with reduced contrast and smaller visual weight
- generous vertical rhythm between major zones
- clean card surfaces with soft borders and subtle glow only when meaningful

---

## Visual tone
Aim for:
- premium
- precise
- calm
- lightweight
- deliberate
- slightly futuristic
- emotionally controlled

Do not aim for:
- aggressive cyberpunk overload
- neon spam
- empty minimalism
- sterile enterprise dashboards
- generic SaaS templates

---

## Typography rules
Typography should feel expensive and legible.

Prefer:
- strong, readable section titles
- restrained overlines
- clear value hierarchy
- secondary text that stays legible in dark mode

Avoid:
- too many tiny uppercase labels
- weak helper text
- washed out opacity
- overdecorated headings

---

## Spacing rules
Use spacing as a design tool.

Prefer:
- wide breathing room around major blocks
- strong internal padding
- separation by rhythm, not excessive outlines
- consistent vertical cadence

Avoid:
- cramped compositions
- box-inside-box-inside-box syndrome
- too many dividers
- dense grids with no breathing room

---

## Workflow

### Step 1 — Diagnose the shell
Before editing, identify:
- what the user sees first
- whether navigation is strong enough
- whether the page has a real visual center
- whether major sections are fighting each other
- whether the layout feels fragmented

### Step 2 — Establish hierarchy
Decide:
- what is primary
- what is secondary
- what is contextual
- what is background support

### Step 3 — Strengthen shell composition
Adjust:
- sidebar clarity
- header/topbar restraint
- main section rhythm
- card sizes
- spacing
- layout hierarchy

### Step 4 — Reduce structural noise
Remove:
- unnecessary wrappers
- redundant visual containers
- over-segmentation
- too many equal-weight blocks

### Step 5 — Refine premium feel
Polish:
- spacing
- contrast
- hierarchy
- subtle motion
- interaction calmness

---

## Quality bar
A successful result should feel:
- stronger
- clearer
- more premium
- less noisy
- more productized
- more readable at a glance

The user should feel:
- “this looks expensive”
- “this feels intentional”
- “I know where to look”
- “this is calm, not chaotic”

---

## Anti-patterns
Do not produce:
- visually loud dashboards
- overdecorated dark UI
- too many accents at once
- thin weak cards with little presence
- empty minimalism with no product confidence
- layouts that look unfinished or lazy

---

## Final validation checklist
Before finishing, verify:
- the shell is clearly stronger than before
- the page has a readable center of gravity
- the sidebar/header/main relationship is obvious
- major blocks breathe
- the layout feels premium, not generic
- the page feels closer to Forja logic without becoming a copy
