# Dark UI Legibility Audit

## Mission
Audit and fix dark interfaces that look stylish at first glance but fail in real reading conditions.

This skill exists to make dark UI:
- readable
- premium
- calm
- comfortable
- credible

A dark interface should feel expensive and confident.
It should not feel muddy, low-contrast, tiny, or tiring.

---

## Use this skill when
Use this skill when:
- text feels too small
- secondary text disappears
- helper text is too dim
- dark surfaces blend together too much
- hierarchy is weak
- the interface looks stylish but reads poorly
- the page feels heavier than it should because of contrast problems

---

## Do not use this skill when
Do not use this skill when:
- the page is not dark UI
- the problem is purely data logic
- the issue is structural architecture rather than readability

---

## Core philosophy
Dark UI is harder than it looks.

This skill should always favor:
- readable contrast
- controlled depth
- calm hierarchy
- comfortable text sizes
- clean value emphasis

The goal is not bright UI.
The goal is **clear dark UI**.

---

## Non-negotiable principles

### 1. Useful text must stay readable
If the text matters, it cannot fade into the background.

### 2. Secondary does not mean invisible
Secondary text can be softer, but still must read comfortably.

### 3. Contrast must support hierarchy
Hierarchy should come from contrast, scale, spacing, and weight together.

### 4. Dark surfaces need separation
Cards, panels, and backgrounds must not collapse into one muddy layer.

### 5. Tiny text is expensive-looking only in mockups
In real use, tiny text often feels weak and careless.

---

## What to audit
Always inspect:
- font sizes
- line height
- opacity values
- color contrast
- helper text
- label readability
- card/background separation
- state visibility
- button readability
- active vs inactive states

---

## Typography guidance
Prefer:
- readable helper text
- minimum practical sizes
- stronger values and titles
- disciplined use of overlines
- cleaner body/support text

Avoid:
- too much ultra-small text
- overuse of faint gray
- thin text on low-contrast surfaces
- important text with decorative opacity

---

## Surface guidance
Prefer:
- subtle but clear card separation
- enough tonal difference between layers
- dark surfaces with clear role distinction

Avoid:
- muddy layers
- too many nearly-identical dark shades
- surfaces that merge into one block

---

## Workflow

### Step 1 — Identify failures
Find:
- unreadable support text
- muddy layers
- weak labels
- weak active states
- poor hierarchy

### Step 2 — Fix text hierarchy
Strengthen:
- primary
- secondary
- helper
- metadata
- values

### Step 3 — Fix surface contrast
Adjust background, border, and separation logic.

### Step 4 — Validate interaction states
Check hover, focus, active, disabled, expanded states.

### Step 5 — Validate on realistic screen conditions
Assume laptop and normal user conditions, not only perfect monitors.

---

## Quality bar
A successful result should make the UI feel:
- easier to read
- more premium
- more trustworthy
- less muddy
- less tiring

---

## Anti-patterns
Do not produce:
- washed-out helper text
- unreadable secondary labels
- “cool” but weak contrast
- decorative darkness with poor usability
- hyper-subtle states that users miss

---

## Final validation checklist
Before finishing, verify:
- useful text is readable
- secondary text is still legible
- cards and surfaces separate clearly
- hierarchy is stronger
- the UI feels more premium and less muddy
