# Content Compressor

## Mission
Compress interface content so the product speaks with clarity, not noise.

This skill exists to remove verbosity from:
- dashboard cards
- mission pages
- KPI helpers
- educational previews
- learning modules
- contextual explanations
- system guidance

The goal is not just “less text”.
The goal is:
- sharper text
- more useful text
- more scannable text
- more premium product language

---

## Use this skill when
Use this skill when:
- cards are talking too much
- support text repeats the obvious
- many blocks have mini paragraphs
- the interface feels heavy because of writing
- the page reads like documentation instead of product
- educational screens need to become more operational

---

## Do not use this skill when
Do not use this skill when:
- long-form explanation is the actual purpose
- the screen is a lesson/article page
- legal/compliance language must remain explicit
- compression would remove necessary clarity

---

## Core philosophy
Good interface writing is:
- short
- precise
- actionable
- quiet
- confident

This skill should always favor:
- signal over explanation
- clarity over cleverness
- compression over redundancy
- operational tone over narrative sprawl

---

## Compression principles

### 1. Do not explain what the UI already shows
If the graph, number, or hierarchy already communicates it, remove the text.

### 2. Replace paragraphs with signals
Prefer:
- short state lines
- short support text
- concise summary phrases

### 3. Keep one idea per block
A card should not narrate multiple layers of meaning at once.

### 4. Context first, then action
Text should orient quickly, then support the next move.

### 5. Compression must not feel robotic
Shorter should still feel elegant, warm enough, and product-quality.

---

## Good outcomes
Good compressed content feels:
- direct
- premium
- light
- intelligent
- readable in seconds

Bad compressed content feels:
- robotic
- vague
- empty
- lazy
- generic

---

## Compression patterns to prefer
Prefer patterns like:
- “Recovery mode”
- “2 critical pending items”
- “Open discipline”
- “3 questions to solve”
- “Next step”
- “Main bottleneck”
- “Review today”

Avoid patterns like:
- “This section helps the user understand...”
- “The following card presents information regarding...”
- “This chart shows how...”
- “You can use this area to...”

---

## Workflow

### Step 1 — Identify redundancy
Find text that:
- repeats titles
- repeats metrics
- explains visible UI
- narrates the obvious

### Step 2 — Compress structure
Reduce each block to its essential message.

### Step 3 — Preserve meaning
Keep enough context so the UI still makes sense quickly.

### Step 4 — Improve tone
Make the text sound premium, calm, and sharp.

### Step 5 — Validate scan speed
The user should understand the block faster after compression.

---

## Quality bar
A successful result should make the UI feel:
- lighter
- clearer
- more premium
- less noisy
- more product-like

---

## Anti-patterns
Do not produce:
- vague microcopy that says nothing
- empty minimalism
- awkward machine-like phrasing
- “fancy” but confusing short labels
- compression that removes necessary meaning

---

## Final validation checklist
Before finishing, verify:
- text is shorter
- meaning is preserved
- the UI scans faster
- tone still feels premium
- cards no longer behave like mini paragraphs
